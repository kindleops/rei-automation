A1 public.mv_map_market_sales  <<< MARKET INTELLIGENCE SALES SOURCE OF TRUTH >>>
  Meaning:
    - One row per deduplicated economic sale (ic8_txn_dedupe@1 parity) over the last 5 years, geocoded.
    - Built from comp_private.comp_canonical_transactions plus the engine pool's MLS closes.
  Freshness:
    - Data through 2026-09-10 (max sold_on). MV refreshed daily by pg_cron refresh_map_market_sales at 10:07 UTC, VACUUM ANALYZE at 10:37.
  Size: 665,288 rows; heap 180 MB, 283 MB total. Service_role only.
  Counts:
    - priced (price > 0): 549,879
    - valid 5-digit ZIP: 655,702 | city 657,831 | state 665,288 (33 states)
    - sqft 536,401 | ppsf 453,687 (ppsf already excludes portfolio sales)
    - units > 0: 347,109
    - portfolio (≥2 parcels, same buyer/date/price): 947
    - source mls: 11,820
    - doc_type present: 631,044
  Indexes:
    - comp_id (unique); (lat,lng) INCLUDE (sold_on, price, per_door, ppsf, source, buyer_class, is_investor, portfolio_size); sold_on; buyer; portfolio; property_id.
    - There is NO zip / state / city index. Any per-geography filter is a full parallel seq scan:
      - one ZIP, cold: 1.02 s (23,064 buffers read)
      - warm: 0.47–0.72 s
  !! COVERAGE WINDOW (critical):
    - Monthly sales are about 150–400 a month through 2025-08 (a sparse legacy channel).
    - Then 36,378 (2025-09), 55,043, 46,474 ... 68,906 (2026-06), 63,821 (2026-07), 41,340 (2026-08), 2,284 (2026-09, partial to 09-10).
    - 609,603 of 665,288 rows (91.6%) fall in the last 365 days.
    - So the corpus is a ~12-month import window. Any YoY growth or 3Y/All trend before 2025-09 would compare an import boundary, not the market.
    - DECISION: trends/growth are computed only inside the measured coverage window. It is derived from the data: the first month whose count reaches ≥25% of the trailing-12 median. Earlier months render as "pre-coverage". No growth % without a baseline inside the window.
  Property types (raw; 7 values):
    - Single Family 528,715
    - Vacant Land 83,257
    - Other 25,417 (1,773 with units > 1)
    - Multi-Family 19,962 (12,127 with units > 1)
    - Apartment 7,933 (5,477 units > 1)
    - Townhouse 3
    - Mobile Home 1
    - NO commercial label exists in the corpus, so the Commercial filter = unavailable.
  Doc types:
    - Warranty 239,772 · Deed 116,510 · Special Warranty 108,814 · Grant 76,302 · null 34,244
    - Quit Claim 19,631 (median $140K, is_arms_length false)
    - Public Action 1,624 (median $8,100)
    - Gift / TOD / Correction / Re-recorded: small, nominal prices.
  DECISION (mi_qualified_price@1): price statistics (median price, PPSF, price/unit) use priced sales that satisfy all of:
    - price > 0
    - portfolio_size < 2 (a bulk price is not a per-property price)
    - is_arms_length IS DISTINCT FROM false
    - doc_type NOT ~* quit claim | gift | transfer on death | correction | re-recorded | public action
    Unpriced and non-qualified rows still count as SALES ACTIVITY (owner price rule §47).

A2 investor purchases = mv_map_market_sales.is_investor (IC8 isInvestorPurchase parity)
  Total: 13,183. buyer_class: unknown 612,522 · individual 33,115 · llc_investor 16,918 · institutional 1,573 · portfolio 678 · bank 349 · government 103 · builder 19 · trust 11.
  !! BUYER EVIDENCE IS THIN:
    - buyer_kind (a recorded buyer) exists on ~41K of 665K sales (6.2%).
    - 37,353 of those are in 2026-05/06, about 260–750 a month 2025-09..2026-04, and 0 in 2026-08/09.
    - Investor purchases by month: 158 … 497 … 3,715 (2026-05), 3,379 (2026-06), 67, 0, 0.
  DECISION:
    - investor_purchase_share = investor purchases ÷ sales WITH a recorded buyer. Never ÷ all sales, which would understate the share 16×.
    - Buyer-evidence coverage (buyer-known ÷ sales) is always shown beside it.
    - Insufficient sample below 20 buyer-known sales.
    - The investor trend is labelled with buyer coverage per month. A month with no buyer evidence is a gap, never 0%.

  DECISION: cash_purchase_share = cash ÷ cash-evidence-known. Coverage shown. Insufficient below 20 known.

======================================================================
G. PERFORMANCE FINDINGS → ARCHITECTURE DECISION
======================================================================
Measured:
- National one-level exact medians (state × asset, 12M, work_mem 64MB): 6.6 s.
- MN grouping-sets snapshot with county join: 4.9 s; without county join: 3.0 s (disk-spilled sort).
- National 6-level × asset grouping sets: projected about 40 s, which exceeds the 30 s timeout. REJECTED.
- Ordered keyset chunk by comp_id: 2.3 s per 50K rows (random heap). REJECTED.
- Full compact sequential extract (\copy, 19 cols): 4.4 s wall, 69 MB text.
DECISION (V1, no migrations):
  The API holds ONE in-memory columnar MARKET SALES INDEX of mv_map_market_sales.
  - Loading: a single REPEATABLE READ READ ONLY transaction (consistent snapshot) with a server-side cursor over a sequential scan, fetched in chunks. The qualification flag and asset code are precomputed in SQL; no property ids or person names are loaded.
  - Reloaded only when the MV changes: max(sold_on) / reltuples probe, a few ms; at most once a day after the 10:07 UTC refresh. Single-flight.
  - Every overview, ranking, screen, compare, trend and heat request is exact and computed in-process, with 0 DB queries per interaction.
  PROPOSED for later: a nightly rollup MV (PROPOSED_ migration) so cold start no longer streams 665K rows.
