# Farsi + Thai first-touch templates — owner wording review

Status: **DRAFT, not inserted, not active.** Script: `apps/api/scripts/repairs/20261004060000_farsi_thai_templates.sql` (ends in ROLLBACK).

Prepared 2026-10-04 to close the language template coverage seam: eligible Minneapolis sellers include 6 Farsi and 3 Thai speakers, and no template exists in either language, so they are held at launch (`unsupported_language`).

## How these were built

- Source: the 306 live `Indian (Hindi or Other)` ownership_check S1 first-touch rows, the existing translated grid. Each new row copies one Hindi row's structure (scope, property groups, phrase type, reply mode, identity mode) and its English source text, so Farsi and Thai get the same 306-row rotation the other 15 languages have.
- The grid is built from parts: greeting x intro x optional middle line x ownership question. The Farsi and Thai versions are built from the same parts, translated below. There are 102 distinct bodies per language (the source grid repeats each body 3 times, under its Hi/Hey/Hello English variants).
- Variables are the ones the catalog uses: `{{seller_first_name}}`, `{{agent_name}}`, `{{property_address}}`, `{{city}}`, `{{zip}}`, `{{county}}`. Each row has the same set as its Hindi sibling (checked by the generator).
- **Script.** Every translated set in the catalog is ASCII romanization (Hindi "Namaste … ke malik hain?", Arabic "Marhaba … tamlik", Mandarin pinyin with no tone marks). This keeps texts in GSM-7, so one segment holds 160 characters instead of 70. These drafts follow that convention: Farsi in Finglish, Thai in RTGS-style romanization with no tone marks. The one exception is the 🙂 variants, which already force UCS-2 in every language.
- **These are machine-drafted.** Before approval, have a native Farsi speaker and a native Thai speaker read them. Romanized Thai without tone marks is easy to misread. If you would rather pay the UCS-2 cost for native script (فارسی / ภาษาไทย), say so and I'll regenerate the drafts from these same parts.
- **Thai politeness.** The drafts use the male particle *khrap* and male *phom* ("I"), matching agent "Alex". A female agent persona would need *kha* and *chan/dichan* instead.
- **Farsi register.** The drafts use formal *shoma … hastid*, which is the right register for a cold first text.
